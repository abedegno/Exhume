# Runtime: the porting harness

The C that a native port of a matched decompilation builds against: the portability layer, the platform layer and its SDL3 backend, the emulated PC hardware (VGA, EMS memory, PIT), Borland's C library where the host's differs, a library for Miles AIL 2 games and its drivers, the x86 machine that translated assembly runs on, record and replay, and the black box. It was written for UW2's port (in UW2Decomp, now Underworld Exhumed's `uw2/`) and made independent of UW2; UW1's port builds on it too; nothing here holds game data or code from a game.

It is a library a project builds against in place, never a copy. Exhume's tools compile it where it is (`[port] runtime`, default this checkout's `runtime/`; docs/config.md), and a project with its own build scripts finds the checkout the same way (Underworld Exhumed's tools/exhume.py in each game: `$EXHUME`, else `../exhume`, the repository's submodule, else `.exhume` in the project, else `~/Exhume`) and pins the commit it was proved with, best as a git submodule (docs/port.md). The project keeps only what is its own: a few bindings headers that say what is the game's, and the C written from or for its game. docs/port.md, "The runtime", has the build arrangement, and each file's first comment says what it is for.

## What is here

- `include/portable.h`: the macros the shared sources use to build for DOS and the port alike (explicit widths, `NEARPTR`, `NULLTRAP`, `FARNULLREC`, `FAR_COPY`, `AX_RESULT`, `STACK_JUNK`, `PLANAR_STORE`, `FILE_RECORDS`, `FRAME_LEN`, `FRAME_INDEX`, `TABLE_NEXT`, `WRITABLE_STR`, `DOS_SIZEOF`, `TAG_SLOT`, `RENDER_TAG` and the rest) and the record and replay hooks. Under Turbo C every one is the original tokens. The DOS build stages it beside the project's own shared headers (tools/build.py), so the gate proves it costs no byte.
- `replay/replay.c`: the record and replay harness and the state dump (recording format 4), compiled by the replay DOS build and by the port. Its first comment has the recording and dump formats, the environment switches (`UWRPCK`, `UWRPFB`, `UWRPTRACE`, `UWRPFULL`, `UWRPHOOK`) and the black box's recording mode.
- `port/compat.h` and `port/include/`: the portability layer, force-included into every game source compiled for the host, and the stand-ins for Borland's headers.
- `port/port.h`: what the port's own C shares: diagnostics, the paragraph map, the EMS memory, the emulated hardware's entry points, finding the game and the settings file.
- `port/platform/`: the SDL-free platform API (`plat.h`), the parts any POSIX host shares (`files.c`, the data root under the home directory with DOS paths matched without case; `png.c`) and the SDL3 backend (`sdl3/plat_sdl3.c`), the only file that includes SDL. The backend hides the host's pointer over the picture (the game draws its own cursor) and, with `PlatConfig.mouse_lock`, captures the pointer on a click as DOSBox does, Ctrl+F10 releasing it; each pointer event says whether its position is where the host's pointer is (`PlatPointer.absolute`), and docs/port.md, "The platform layer", has how a mouse driver makes the game's cursor follow it. It also gives the window the project's icon (`PLAT_ICON`) and has a message box and a folder picker for before the window opens (`plat_message`, `plat_choose_folder`) and the program's own directory (`plat_base_dir`).
- `port/mem/parmap.c`: the paragraph map, Borland's far heap, `movedata`, and the null-pointer copies, which the project fills (`port_game_nulls`). `port/mem/frame.c`: an EMS page frame mapped twice in a row so a far pointer's offset wraps at 64 KB (macOS, Linux, Windows). `port/mem/emm.c`: the EMS 4.0 driver's memory for a game with one handle, a store of logical pages and four frame slots, in which a page mapped into two slots stays one page; the project's C keeps the game's own EMS entry points over it (`emm_open`, `emm_map`, `emm_close`).
- `port/gfx/vga.c`: the VGA: planes, map mask, latches, read map, display start, panning, line compare, the DAC, the retrace bit, and the scan-out the platform layer presents, with the display start and the pixel panning latched at the retrace as the CRT controller latches them (`vga_scanout`), or as the registers stand for a screenshot the game's own thread takes (`vga_scanout_now`).
- `port/sys/borland.c`: Borland's C library where the host's differs (handle I/O with text mode, streams read and written on their handles, DOS paths, host paths for the port's own files that DOS could not name (`bc_open_host`: the black box's recording), binary host handles on Windows, `findfirst`, `intdosx` reads and writes, `getvect` and `setvect`, port I/O, the string extras, `_ctype`, Borland's `rand`, `clock` at 18.2 Hz, `exit`); `records.c`, `FILE_RECORDS` and `FARNULLREC` on the host; `crash.c`, the call stack on a host fault; `blackbox.c`, the black box (below); `gamedir.c` and `gogreg.c`, finding the user's copy of the game (a folder the user names, GOG's install folders and, on Windows, GOG's registry entries, a game inside GOG's CD image copied out once) and the port's settings file (`port_find_game`, `port_game_in`, `port_config_get`, `port_config_set`). `pace.c`, the 3D frame pacing (`port_pace_frame`: a frame waits until `PORT_FRAME_TICKS`, 8, ticks of the game's clock have passed since the last, never under replay; the Underworlds drop the fraction of the player's move each frame, so at a frame a tick slow moves towards +x or +y are lost).
- `port/sound/`: a library for Miles AIL 2 games: AIL's API (`ail.c`, from UW2's matched AIL.ASM, with the timer DDA, the replay's sound reads and the driver logs) and its drivers in C from AIL 2.14's public-domain source (`xmidi.c`, `yamaha.c`, `mt32.c`, `dmasound.c`), over `audio.c`, the card (Nuked OPL3, libmt32emu, the Sound Blaster DAC; fetched or linked, never committed: docs/third-party.md). `mt32roms.c` finds the user's MT-32 or CM-32L ROMs by their contents (libmt32emu's identification), from a path given (a folder or a file), the environment, the remembered setting or a search of the usual folders, DOSBox Staging's among them, a CM-32L pair first; split halves are joined (`mt32roms_add`). The platform layer's `drop` hook passes a folder dropped on the window or the macOS app, for a project to use the same way. `yamaha.c` is YAMAHA.INC as released (without `OSI_ALE`), with a hook for game-specific FM extensions such as Origin's time-variant effects (TVFX), which a project supplies from its own decompilation: `struct AilFmExt` in `yamaha.h`, the extension's source named in `[sound] extensions` and its symbol in `ailgame.h` as `AIL_FM_EXT`; yamaha.h says exactly what a TVFX timbre does without one. The third-party macros are `AUDIO_HAVE_OPL` and `AUDIO_HAVE_MT32EMU`. `port/sys/pit.c` is the PIT thread that drives it.
- `port/stubs/`: the body every generated link stub calls (tools/portstubs.py writes the stubs, in the project).
- `port/x86/asmrt.h`, `asmrt.c`: the machine tools/asm2c.py's translations run on (registers, flags, segment bases, the emulated stack, calls that follow jumps until the stack says they returned, the divide fault, the glue to hand-written C).

A project that does not need a part leaves it out with `[port] runtime_exclude` and supplies what replaces it in its own C (a game without AIL 2 would leave out `port/sound` and give the PIT thread's AIL calls something else to drive).

## The project's side

The runtime's headers include the project's bindings by fixed names, found on the include path ahead of the runtime's own directories. A project writes these, and nothing else of the runtime's:

| File (where) | Included by | What it says (UW2's, in Underworld Exhumed's uw2/) |
| --- | --- | --- |
| `hookgame.h` (the shared headers, an 8.3 name) | `include/portable.h`, first | the original tokens of the hooks it uses: `ORIG_GAME_TIME()`, `ORIG_KEY()`, `ORIG_MOUSE()`, `ORIG_MBUTTONS()`, `ORIG_JOY_READ()`, `ORIG_JOY_BUTTONS()`, `SLAVE_TIMER_HZ`, `RENDER_TAG_CONTEXT`; may be empty (src/include/hookgame.h) |
| `rpgame.h` (the shared headers) | `replay/replay.c` | what the hooks read and what the dumps hold: `RP_MAGIC`, `RP_CLOCK`, the key state, the mouse and joystick, `RP_SHUTDOWN()`, the clock's tick and PIT divisor, C0's null checksum, `RP_LEVEL`, `RP_NSECTIONS` and `RP_DUMP` (replay.c's first comment; src/include/rpgame.h) |
| `portgame.h` (`[port] dir`) | `port/port.h`, `compat.h`, `plat.h`, the sound and system C | `PORT_NAME`, `PORT_GAME_MAIN`, `PORT_DGROUP_PARA`, `PORT_CTYPE_AT`, `PORT_EXIT_CHAIN()`, the load segment and far heap if not the defaults, the black box (`PORT_BLACKBOX`, `BLACKBOX_KEEP`, `BLACKBOX_SKIP`), the window (`PLAT_NAME`, `PLAT_TITLE`, `PLAT_ICON`), finding the game (`PORT_GAME_EXE`, `PORT_GAME_FOLDER`, `PORT_GAME_HINTS`, `PORT_GAME_DESC`, `PORT_GOG_ID`, `PORT_DATA_ENV`, `PORT_GAME_ROOTS`, `PORT_CONFIG_FILE`, `PORT_CONFIG_TITLE`: sys/gamedir.c's first comment), the sound library's environment variables (`AIL_SNDCHECK_ENV`, `AUDIO_ROMS_ENV`), and the program's own far blocks. compat.h brings it into the game's C too, so it declares only the port's names (src/port/portgame.h) |
| `asmgame.h` (`[port] dir`) | `port/x86/asmrt.h` | the code blocks the translations read (`CODEnnn`, `ASM_CODE_BASE`), a dispatcher of the project's own (`ASM_HAND_HANDLED`, `ASM_HAS_FALLBACK`, `ASM_FALLBACK`), `ASM_TRACE_ENV` (src/port/asmgame.h) |
| `ailgame.h` (`[port] dir`) | `port/sound/ail.c`, first | compat.h, the game's own declarations of the AIL API, and `AIL_FM_EXT` (src/port/ailgame.h) |

and the C the runtime calls: `port_load_exe` and `port_check_exe` (the far data from the user's EXE, and whether a file is the build the port was made from), `port_game_nulls` (what DOS reads through a null pointer), `asm_divfault` (the program's divide fault handlers), the glue table (`asm_glues`), and the port's `main` with its diagnostics (`port_log`, `port_fatal`, `port_halt`, `port_on_flip`). The rest of what is the game's own stays in the project: the C that replaces its assembly modules and DOS-only C, the translated modules, its mouse driver (which needs the game's cursor), its EMS entry points, and anything translated from its drivers (UW2: tvfx.c).

## The black box

A player's run of the port records its session, so that a crash report can carry a recording that replays the crash exactly (docs/port.md, "The black box"). `port/sys/blackbox.c` gives each session a folder, `recordings/YYYYMMDD-HHMMSS` in the port's home directory, with `RECORD.OUT` and `stage/` (a copy of the home directory's files as the session began), keeps the newest `BLACKBOX_KEEP` (5), and puts replay.c into its black box mode (`rp_blackbox`: no state dumps, no stop key, the header's call count always FFFFFFFFh, however the session ends). Exhume has no main; the project's main wires it:

1. In `portgame.h`: `#define PORT_BLACKBOX 1`, so that crash.c's fault handler and borland.c's `bc_exit` call `port_blackbox_close`, and `BLACKBOX_SKIP` with the names in the home directory that are the port's own rather than the game's (its settings file, its logs), as string literals separated by commas (UW2: `"uw2port.cfg"`).
2. In main, after the home directory and `rp_request` are settled and before the game's thread starts: `if (interactive && recording && rp_request == 0) port_blackbox_start(home);`, where `interactive` is a run with a window (not `--hidden`), `rp_request == 0` means neither `--record` nor `--replay`, and `recording` is cleared by an option such as UW2's `--no-recording`.
3. In main, when `plat_run` returns (the window closed, or the run's time is up, with the game still running): `port_blackbox_close(0);`, which writes out the recording's last runs and chunks, a `--record` session's too. Without it a session ended by closing the window loses what was still buffered, and its replay ends at the first read of a stream it never got.
4. Tell players where the recordings are and to attach the newest folder to a bug report. Replay one with `tools/replay.py port recordings/S/RECORD.OUT OUT --stage recordings/S/stage`: the replay runs to the end of the streams, or into the crash.

A game that polls sound state in a tight loop makes a run per call (UW2: two digital buffers' status read in turn, 2, 0, 2, 0, about 900 MB in six minutes of black box); recording format 4 writes a continued repeat of the last one to four sound runs as one entry, and replay.c reads formats 2 to 4.

## Proved on UW2

UW2Decomp builds against this runtime in place, with no copy of it (examples/uw2/prove-port.sh, every step; examples/uw2/port/README.md has the results): its gate passes with the runtime's portable.h, Exhume's tools and UW2Decomp's own build byte-identical ports from it, all ten sessions verify against goldens made in DOS (and the replay DOS build made with replay.c reproduces each in DOSBox-X, twice), the fuzzing is clean, the drivers' writes are the real `.ADV` drivers', and the WAV of a whole session is byte-identical to that of UW2Decomp v1.2.0, the last release with its own copies. A black box recorded by v1.2.0 replays to its end. What stays UW2's own, and why, is in docs/port.md, "The runtime".
