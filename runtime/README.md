# Runtime: reference C for a native port

C that a port of a matched decompilation compiles, taken from UW2Decomp's port and made independent of UW2 where that was cheap. A project copies what it needs into its own tree (UW2Decomp keeps them under `src/include`, `src/replay` and `src/port`) and adapts it there; Exhume's tools find them through exhume.toml's `[port]` and `[replay]` (docs/config.md). Nothing here holds game data or code from a game: everything game-specific is a small bindings file the project writes, and examples/uw2/port/ has UW2's. docs/port.md is the method; each file's first comment says what it is for.

- `include/portable.h`: the macros the shared sources use to build for DOS and the port alike (explicit widths, `NEARPTR`, `NULLTRAP`, `FARNULLREC`, `FAR_COPY`, `AX_RESULT`, `STACK_JUNK`, `PLANAR_STORE`, `FILE_RECORDS`, `FRAME_LEN`, `FRAME_INDEX`, `TABLE_NEXT`, `WRITABLE_STR`, `DOS_SIZEOF`, `TAG_SLOT`, `RENDER_TAG` and the rest) and the record and replay hooks. Under Turbo C every one is the original tokens. A project defines the hooks' original tokens before it (`ORIG_GAME_TIME()` and so on; UW2's: examples/uw2/port/portable-uw2.h).
- `replay/replay.c`: the record and replay harness and the state dump, compiled by the replay DOS build and by the port, with the game's side in `rpgame.h` (UW2's: examples/uw2/port/rpgame.h). Its first comment has the recording and dump formats, the environment switches (`UWRPCK`, `UWRPFB`, `UWRPTRACE`, `UWRPFULL`, `UWRPHOOK`) and the black box's recording mode.

- `port/compat.h` and `port/include/`: the portability layer, force-included into every game source compiled for the host, and the stand-ins for Borland's headers. The project names its main (`PORT_GAME_MAIN`; UW2's: examples/uw2/port/compat-uw2.h).
- `port/port.h`: what the port's own C shares (diagnostics, the paragraph map, the emulated hardware's entry points), with the program's side in `portgame.h` (examples/uw2/port/portgame.h).
- `port/platform/`: the SDL-free platform API (`plat.h`, with `PLAT_NAME` and `PLAT_TITLE` from the project: examples/uw2/port/plat-uw2.h), the parts any POSIX host shares (`files.c`, the data root under the home directory with DOS paths matched without case; `png.c`) and the SDL3 backend (`sdl3/plat_sdl3.c`), the only file that includes SDL. The backend hides the host's pointer over the picture (the game draws its own cursor) and, with `PlatConfig.mouse_lock`, captures the pointer on a click as DOSBox does, Ctrl+F10 releasing it, the window's title saying which; each pointer event says whether its position is where the host's pointer is (`PlatPointer.absolute`), and docs/port.md, "The platform layer", has how a mouse driver makes the game's cursor follow it.
- `port/mem/parmap.c`: the paragraph map, Borland's far heap, `movedata`, and the null-pointer copies, which the project fills (`port_game_nulls`; examples/uw2/port/nulls-uw2.c). `port/mem/frame.c`: an EMS page frame mapped twice in a row so a far pointer's offset wraps at 64 KB (macOS, Linux, Windows).
- `port/gfx/vga.c`: the VGA: planes, map mask, latches, read map, display start, panning, line compare, the DAC, the retrace bit, and the scan-out the platform layer presents, with the display start and the pixel panning latched at the retrace as the CRT controller latches them (`vga_scanout`), or as the registers stand for a screenshot the game's own thread takes (`vga_scanout_now`).
- `port/sys/borland.c`: Borland's C library where the host's differs (handle I/O with text mode, DOS paths, `findfirst`, `intdosx` reads and writes, `getvect` and `setvect`, port I/O, the string extras, `_ctype`, Borland's `rand`, `clock` at 18.2 Hz, `exit`); `records.c`, `FILE_RECORDS` and `FARNULLREC` on the host; `crash.c`, the call stack on a host fault; `blackbox.c`, the black box (below).
- `port/sound/`: a library for Miles AIL 2 games: AIL's API (`ail.c`, from UW2's matched AIL.ASM, with the timer DDA, the replay's sound reads and the driver logs) and its drivers in C from AIL 2.14's public-domain source (`xmidi.c`, `yamaha.c`, `mt32.c`, `dmasound.c`), over `audio.c`, the card (Nuked OPL3, libmt32emu, the Sound Blaster DAC; fetched or linked, never committed: docs/third-party.md). `yamaha.c` is YAMAHA.INC as released (without `OSI_ALE`), with a hook for game-specific FM extensions such as Origin's time-variant effects (TVFX), which a project supplies from its own decompilation: `struct AilFmExt` in `yamaha.h`, the extension's source named in `[sound] extensions` and its symbol in `ailgame.h` as `AIL_FM_EXT` (UW2: `uw2_tvfx`, UW2Decomp's src/port/sound/tvfx.c); yamaha.h says exactly what a TVFX timbre does without one. The project's `ailgame.h` brings in compat.h and its own declarations of the AIL API (examples/uw2/port/ailgame.h); `portgame.h` may name the environment variables (`AIL_SNDCHECK_ENV`, `AUDIO_ROMS_ENV`); the third-party macros are `AUDIO_HAVE_OPL` and `AUDIO_HAVE_MT32EMU`. `port/sys/pit.c` is the PIT thread that drives it.
- `port/stubs/`: the body every generated link stub calls (tools/portstubs.py writes the stubs).
- `port/x86/asmrt.h`, `asmrt.c`: the machine tools/asm2c.py's translations run on (registers, flags, segment bases, the emulated stack, calls that follow jumps until the stack says they returned, the divide fault, the glue to hand-written C), with the program's side in `asmgame.h` (UW2's: examples/uw2/port/asmgame.h) and its `asm_divfault`, the program's own divide fault handlers, which stay in the project (UW2: UW2Decomp's src/port/x86/divfault.c).

## The black box

A player's run of the port records its session, so that a crash report can carry a recording that replays the crash exactly (docs/port.md, "The black box"). `port/sys/blackbox.c` gives each session a folder, `recordings/YYYYMMDD-HHMMSS` in the port's home directory, with `RECORD.OUT` and `stage/` (a copy of the home directory's files as the session began), keeps the newest `BLACKBOX_KEEP` (5), and puts replay.c into its black box mode (`rp_blackbox`: no state dumps, no stop key, the header's call count left at FFFFFFFFh). Exhume has no main; the project's main wires it:

1. In `portgame.h`: `#define PORT_BLACKBOX 1`, so that crash.c's fault handler and borland.c's `bc_exit` call `port_blackbox_close`, and `BLACKBOX_SKIP` with the names in the home directory that are the port's own rather than the game's (its settings file, its logs), as string literals separated by commas (UW2: `"uw2port.cfg"`). Link blackbox.c.
2. In main, after the home directory and `rp_request` are settled and before the game's thread starts: `if (interactive && recording && rp_request == 0) port_blackbox_start(home);`, where `interactive` is a run with a window (not `--hidden`), `rp_request == 0` means neither `--record` nor `--replay`, and `recording` is cleared by an option such as UW2's `--no-recording`.
3. Tell players where the recordings are and to attach the newest folder to a bug report. Replay one with `tools/replay.py port recordings/S/RECORD.OUT OUT --stage recordings/S/stage`: the replay runs to the end of the streams, or into the crash.

Proved on UW2 (examples/uw2/prove-port.sh, `runtime`): with these in place of UW2Decomp's own `portable.h` and `REPLAY.C`, the gate passes (every DOS byte the same), the port replays all eight sessions identically to their goldens (and all ten at UW2Decomp's 4b46276, whose sources use `FRAME_INDEX`, `TABLE_NEXT`, `TABLE_PREV`, `FARNULLREC`, `DOS_SIZEOF`, `TAG_SLOT` and the black box), and the replay DOS build, run twice per session in DOSBox-X, reproduces every golden. With asmrt in place of UW2Decomp's own, the port verifies all eight sessions and the routine fuzzing finds no difference. With the whole portability layer above in place of UW2Decomp's own files (UW2's bindings in front), the gate passes, the port builds, verifies all eight sessions and fuzzes clean, portstubs.py finds the stubs current and portcheck.py reports no error (examples/uw2/prove-port.sh, `toolkit`). That last proof predates UW2Decomp's release work: its `main.c` now also calls the platform's dialogs and base directory (`plat_message`, `plat_choose_folder`, `plat_base_dir`) and the game folder and settings helpers (`port_game_in`, `port_config_get`, `port_config_set`), which are not in this runtime yet, so `toolkit` fails at UW2Decomp's current head until they are.

What stays UW2's own, in UW2Decomp, because it is UW2's program rather than a machine: the far data loader (mem/fardata.c, which reads UW2.EXE by its offsets), the EMS driver under EMS.C's entry points (mem/ems.c, though its page store is generic), seg021's start-up and input (sysentry.c, keyqueue.c, mousedrv.c), the divide trap's chain into the game (int0trap.c), the port's main and its options, the hand-written graphics library and renderer C, the glue, and the translated modules. With the sound library and the PIT in place too (UW2Decomp's tvfx.c through yamaha.h's hook), every session still verifies, tools/ailcheck.py finds the drivers' writes identical to the real `.ADV` drivers', and the WAV a whole session renders is byte-identical to UW2Decomp's port's (`sound`).
