# Third-party code and licences

Exhume is MIT-licensed and contains no game data, no Borland binaries and no third-party source. A port built with it uses other people's code; this page records what, under which licence, and how a project gets it without committing it. The rule: never vendor LGPL or GPL code into a project's repository or into Exhume; fetch it at setup, pinned and checked, or link it from a system package.

Exhume holds no code derived from a game. Where a game's drivers or program add code of their own to a third-party library, the runtime has a hook and the project supplies the code from its own decompilation. The FM drivers of AIL 2 games may be built with Origin's time-variant effects (`ALE.INC`, YAMAHA.INC's `OSI_ALE`; UW2's `DM02` to `DM07.ADV` are), whose source was never released: runtime/port/sound/yamaha.c is YAMAHA.INC without them, and `struct AilFmExt` (yamaha.h) is where a project plugs its own translation in (UW2: UW2Decomp's src/port/sound/tvfx.c, translated from DM03.ADV, named by examples/uw2/exhume.toml's `[sound] extensions`). In the same way the static recompiler's overrides for single instructions are the project's (`[asm2c] overrides`; UW2Decomp's tools/asm2c.py), and so is asmrt's divide fault handling (`asm_divfault`; UW2Decomp's src/port/x86/divfault.c). The examples hold a game's names, offsets and constants as configuration, never its routines.

A port's own source, written from the matched assembly and the game's C, is the project's: it holds no byte of the game's data. The translated modules hold only what the committed `.ASM` sources already hold. Far data no source defines yet is read from the user's own EXE at start-up, never shipped.
