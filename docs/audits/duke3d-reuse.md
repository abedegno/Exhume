# Duke v1.3D recovery reuse audit

This audit separates reusable engineering from game-specific and restricted material. It inventories **all 1,673 tracked paths** from recovery commit `099a0400259bac00c18698b0b871af7df7e5f246`, using `git ls-files --stage`. Gitlinks count once; their trees are not silently folded into this inventory. [The JSON inventory](duke3d-reuse.json) contains every path, Git object/mode, exclusive category, rule and rights qualification. No game/SDK source, executable, object, compiler or raw code payload is imported here.

The curated source release is [abedegno/duke3d-1.3d](https://github.com/abedegno/duke3d-1.3d), inspected at `e8b2c6788674fa82f74213ccb9afd56ffc4ae3e1`. Its [verification record](https://github.com/abedegno/duke3d-1.3d/blob/e8b2c6788674fa82f74213ccb9afd56ffc4ae3e1/verification/rebuild.json) identifies the original recovery commit. All paths below refer to that recovery snapshot unless qualified as curated-release paths. They are portable source identifiers, not required filesystem locations.

## Reusable mechanisms and their boundaries

**Formats.** `profiles/watcom/tools/le.py` and `omf32.py` establish bounded LE and OMF32 structures. `tools/native_library.py` and `object_contributions.py` separate archive members and contributions. `logical_segment_origins.py` and `verify_composite.py` show logical origin and composite ownership issues. `bind_dos4gw.py` illustrates a prefix-only container binding boundary. Reuse parsers and invariants behind minimal public fixtures, not game coordinates, private module descriptors, raw target records or assumptions that a data-flagged LE object contains no instructions. The 221-byte MACT assembly contribution is an explicit counterexample to that assumption.

**Runner and setup.** The Watcom runner and three compiler/assembler setup families demonstrate declared tool homes, pinned archives and output/log collection. Reuse explicit environment/identity validation and fresh output handling. Compiler archives, executables, libraries and installation media remain local. The independently licensed Watcom 10.5 preservation unpacker is an external AGPL dependency, not code to absorb under Exhume's license.

**Provenance and proofs.** `prove_module.py`, `verify_module.py`, `infer_bindings.py` and `match_function.py` are references for complete contribution checks: initialized bytes, BSS, typed fixups, publics and private scope. A target-specific descriptor is evidence for Duke, not a reusable universal validator. Provider identities must be independently established, with archive/member hashes and actual native selection where relevant. A masked candidate and a self-derived callee nomination do not establish identity. Pin source, headers, options, tools and actual provider maps; freeze raw outputs and hashes before parsing or staging, then enforce their lifetime through publication. Use explicit exceptions for mandatory validation so `python3 -O` preserves checks.

**Compiler knowledge.** The compiler profile, runtime inventory and stock-runtime preparation show why exact releases and per-compiland switches matter. Watcom GA, 10.0a, 10.0b and 10.5 are not interchangeable; MUSIC uses the patched 10.0b compiler while its base tool/header identities remain 10.0a. Historical makefile options can be more discriminating than further local source rewrites. Ordinary unused declarations or dead stores may be needed for historical allocation/order: retain them when focused positive/negative native controls prove the effect. No instruction-byte arrays, object edits or executable patches qualify as source recovery.

**Source release.** The original `.gitignore`, `.gitmodules` and `tools/preserve.py` provide preservation boundaries. The curated release adds `tools/verify_source_manifest.py`, `tools/import_local_dependencies.py`, `tools/verify_rebuild.py`, `verification/source-manifest.json`, `verification/local-dependencies.json` and a fresh release-tree proof. Those added paths are deliberately not counted as original tracked files. Reuse the pattern: mixed-license notices, public snapshot hash manifest, exact restricted-source overlay manifest/local importer, declared user-supplied inputs and independent fresh curated-checkout reproduction. Do not merely hash a private development executable or link cached recovery objects.

## What the final evidence establishes

The retained recovery result `evidence/root-exact672.json` and its local full receipt `build/task672-root-exact/result.json` establish an **all-121-fresh** optional source-native preparation build. It compiled 121 owned inputs, linked 177 unmodified selected stock compiler-library members plus five original libraries, then bound a separately supplied 217,764-byte DOS4GW prefix (SHA-256 `21d1cda74c1f4e379b5796c8f33a6619dfced9e5b8eef2df642a21b91fc882ff`). Those supplied components earn zero recovered-source credit.

The bound result is **1,179,131 bytes**, SHA-256 **`a197b6b4097fa39987f4a843141830ff1553eb52b606b51fc67d067560de0cf4`**, with **zero differing bytes** under the independent full unmasked observer. Its native program hash before binding is `a5fd6a00453c9f923b6c453a91be2401bfafad3ce55ee6ff741727f2346be88a`. Production reports no target game payload or ignored research object input and fresh owned-source compilation. The exact main-workspace run took about 156 seconds. The curated release independently records a fresh **121-input** release-tree build, the same size/hash, no restricted overlay tracked, and about 161 seconds. These are two distinct provenance checkpoints, not a new build performed by this documentation audit.

The recovery's recipe/receipt fields `preparation_only: true`, `adoption_approved: false` and `whole_target_match: false` record the then-pending adoption policy for seven DATA bytes; they do not negate the external observer's complete file equality. The curated release intentionally selects that exact route as `make rebuild`. Preserve this distinction between producer policy, measured file identity and historical adoption state; do not rewrite old negative receipts as successful ones.

There are **three explicit unknown-DATA groups**: 96 bytes (`src/game/unidentified13d_data.S`), two GF1_OS bytes, and seven post-NUL GAME constant bytes. Their historical declarations, ownership and/or purpose remain unidentified. The literal source representations preserve observed noninstruction data and add no historical-source credit. They are not inferred original C declarations. Existing zero-residue and earlier ordinary-C modes remain available with their recorded differences.

This is source-assisted reconstruction using authored/historical C and named assembly, with C reading aids. GAME's three assembly-reconstructed bodies and ACTORS' `moveeffectors` still have compiler-faithful C lowering limits; C counterparts are not duplicate emitting nodes. Original assembler modules remain assembly. Byte equality does not establish all-C emission, uniquely recovered original spelling, original private names, or ownership of supplied vendor/runtime components. See the [case study](../case-study-duke3d.md).

## Gate levels and optional emitter

Treat masked function candidates, complete contributions, semantic linked images, serialized native images and complete bound files as separate levels. Identical loaded bytes/typed loader operations do not establish relocation record order. Native FILE order, duplicate PUBLIC selection and source-owned record boundaries matter to serialization. Final equality covers the entire header/container, initialized data, pages, relocation serialization and bound prefix with no masks or post-link patches.

The 47 GNU profile paths cover `gnu_omf`, `gnu_elf_omf`, `gnu_elf_omf_imports`, `gnu_elf_omf_game` and `gnu_elf_omf_layouts`. This is an **optional separately licensed** GNU binutils 2.44 / objconv 2.57 source-built emitter pipeline, including GPL patches. [The audited external layout profile](https://github.com/abedegno/duke3d-1.3d/tree/e8b2c6788674fa82f74213ccb9afd56ffc4ae3e1/profiles/gnu_elf_omf_layouts) documents the finite source-owned CODE-span interface. Plans partition fresh compiled ELF/COFF source extents and constrain fields; they carry no target instruction payloads. Exact coverage, no crossings, output-format/old-OMF rejection and immutable RAW outputs are required. Source-derived repeated initializer templates are qualified data, not permission for arbitrary byte payloads. These patches and vendor sources are not copied into or relicensed as MIT Exhume core.

Existing Borland extraction-based links remain valid partial reconstruction stages. Their extracted code/data/gaps are supplied bytes, so an exact extracted link does not itself establish a complete owned-source build. These lessons strengthen reporting and future final gates without silently replacing Borland commands, object timestamp semantics, workflow or acceptance dispatch.

## Rights evidence and work integration

The curated [component licensing inventory](https://github.com/abedegno/duke3d-1.3d/blob/e8b2c6788674fa82f74213ccb9afd56ffc4ae3e1/LICENSE.md), local-dependency manifest and actual file notices govern the boundary: Apogee game/audio source generally retains GPL-2.0-or-later notices (for example `src/audio/task_man.c`); engine/cache retain Ken Silverman's separate Build license; runtime source retains Sybase Open Watcom terms. FORTE/Gravis and Creative source families and associated reconstructions remain local-only. Binaries, banks and media are not included. The separate MACT uncertainty above is a reconstruction-notice/GPL-release interpretation question, not evidence of the FORTE/Creative restrictions. Every file's `rights` value in the JSON is a qualification for review, not a new license conclusion.

The integrated skill changes extend [link-and-diff](../../skills/link-and-diff/SKILL.md), [verify-and-merge](../../skills/verify-and-merge/SKILL.md), [orchestrate](../../skills/orchestrate/SKILL.md) and [readability-pass](../../skills/readability-pass/SKILL.md). Two focused gaps receive [recover-linked-library](../../skills/recover-linked-library/SKILL.md) (historical source discovery before decompilation) and [package-source-release](../../skills/package-source-release/SKILL.md) (curated rights/source/rebuild boundary). Primary license terms and original release grants must be distinguished from our own cautious checkpoint statements. An authorized recovery/edit task does not require invented per-step user approvals. Experiments use bounded controls and compiler budgets; whole builds occur at justified gates. Resolved evidence is reused without repetitive approval questions or unbounded fresh reviewer loops.
