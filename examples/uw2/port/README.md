# UW2's port: configuration and proof

UW2Decomp's native port is Exhume's port tooling's first case (docs/port.md, docs/case-study-uw2.md), and it builds against Exhume's runtime in place: UW2Decomp holds no copy of a runtime file, only its own bindings for it (src/port's `portgame.h`, `asmgame.h` and `ailgame.h`, src/include's `hookgame.h` and `rpgame.h`; runtime/README.md, "The project's side") and the C written from or for UW2. This directory holds the files the generic tools take as UW2's configuration; the rest of UW2's port configuration is in examples/uw2/exhume.toml (`[port]`, `[replay]`). UW2's names, offsets and constants are here as configuration; none of UW2's code is. What is translated from UW2 or its drivers stays in UW2Decomp: the FM drivers' time-variant effects (src/port/sound/tvfx.c, `[sound] extensions`), the renderer's divide fault handlers (src/port/x86/divfault.c, `asm_divfault`) and asm2c's overrides (tools/asm2c.py, `[asm2c] overrides`).

- `fuzz_targets.py` and `fuzzhost-uw2.c`: tools/fuzzasm.py's 35 UW2 targets (IMATH, INSTANCE, SPHERE, GRENTRY, CLIP, EXPAND) and fuzzhost.c's UW2 side (the far data, seg021's data and the code block as regions; cSinCos, cFstSinCos, cSqRt, cAtan2 and seg004_uncmp as call kinds).
- `asm2c_spec.py`: tools/asm2c.py's spec: the 26 modules UW2Decomp translates (14 of seg004, 11 of seg003, IMATH), the code segments, the hand-written ranges, the C names the overrides use. The overrides themselves, C for single instructions of UW2's, are UW2Decomp's tools/asm2c.py's (`[asm2c] overrides`).

`../prove-port.sh` proves the tools and the runtime on a snapshot of UW2Decomp, writing nothing into the checkout (`PATCH=FILE` applies a change for UW2Decomp to every snapshot first, to prove it before it is committed there):

- `build`: Exhume's gate passes; Exhume's portbuild.py links a `uw2port` byte-identical to the one UW2Decomp's own portbuild.py links in the same tree (all 180 objects equal, the runtime's compiled where it is by both); Exhume's replay DOS build, which compiles the runtime's replay.c, is the EXE the committed goldens were made with (the same SHA-256).
- `verify`: Exhume's `replay.py verify all` finds all ten sessions identical to UW2Decomp's committed goldens, at all 675 checkpoints, saved games included. With `--dos`, `replay.py golden all --check` replays each session twice in DOSBox-X and finds both runs identical to the golden.
- `runtime`: the snapshot holds no copy of any of the runtime's 40 C files and headers (none of their names in src/port, src/include or src/replay, and no file with their contents), and has its five bindings; built against this checkout's runtime the gate passes (so the runtime's portable.h costs no DOS byte), the port verifies all ten sessions, and with `--dos` the replay DOS build made from the runtime's replay.c reproduces every golden in DOSBox-X, each session twice.
- `fuzz`: Exhume's fuzzasm.py with these targets runs 5,560 cases of the 35 routines with no difference, the same report as UW2Decomp's fuzzasm.py but for the timings; a target changed to compare registers the C is known not to set (`expand.pal_63` with every register) fails in every case, so the comparison is live.
- `asm2c`: Exhume's asm2c.py --check finds UW2Decomp's translations up to date; with the 27 generated files deleted from a snapshot, it writes all 27 again byte-identical to UW2Decomp's committed ones, and with them and the runtime's asmrt the port builds, verifies all ten sessions and fuzzes clean.
- `toolkit`: Exhume's portcheck.py, portstubs.py --check, widths.py --diff, intaudit.py and layoutcheck.py give the same output as UW2Decomp's own tools in the same tree (portcheck: 99 sources, 0 errors; layoutcheck's DOS and host probe outputs too: 46 records, 38 identical, every file record identical).
- `sound`: Exhume's ailcheck.py on the port built with the runtime finds every register write and MIDI byte identical to the real drivers' (DM03.ADV: 13,608 writes over 195 calls in `sound`, 14,041 over 270 in `soundfm`; DM05.ADV: 25,726 bytes over 280 calls in `soundmt`); and the WAV file of everything the cards play in the whole `sound` and `soundfm` sessions is byte-identical to the one UW2Decomp v1.2.0's port renders (`BASE=22eaf53`, its last commit with its own copies of the runtime).
- `ci`: tools/citemplates.py with examples/uw2/ci.toml writes UW2Decomp's four workflows and two actions byte-identical to its `.github`, the Exhume checkout at the commit tools/exhume-ref names included, and actionlint finds nothing in them or in the defaults' instantiation; tools/ci-assets.sh, given UW2's paths, prints and writes what UW2Decomp's own does on a dummy bundle encrypted with a throwaway age key.

Run on 4 October 2026 against UW2Decomp v1.2.0 (22eaf53) with the change that moved it onto the runtime as `PATCH`, before either was committed.
