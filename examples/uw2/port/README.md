# UW2's port: bindings and proof

UW2Decomp's native port is Exhume's port tooling's first case (docs/port.md, docs/case-study-uw2.md). This directory holds what is UW2's own: the bindings that instantiate Exhume's reference runtime for UW2, and the files the generic tools take as configuration. The rest of UW2's port configuration is in examples/uw2/exhume.toml (`[port]`, `[replay]`). UW2's names, offsets and constants are here as configuration; none of UW2's code is. What is translated from UW2 or its drivers stays in UW2Decomp, and the bindings point at it: the FM drivers' time-variant effects (src/port/sound/tvfx.c, `[sound] extensions`), the renderer's divide fault handlers (src/port/x86/divfault.c, `asm_divfault`) and asm2c's overrides (tools/asm2c.py, `[asm2c] overrides`).

- `portable-uw2.h`: the original tokens of UW2's replay hooks (`ORIG_GAME_TIME()` is `(*Time)`, and so on), `SLAVE_TIMER_HZ` and `RENDER_TAG_CONTEXT`. UW2Decomp's `src/include/portable.h` is runtime/include/portable.h with these in front.
- `rpgame.h`: UW2's bindings for runtime/replay/replay.c: the clock, the key state, the mouse and joystick, the shutdown, the AIL timer's period and PIT divisor, and the dump's sections (the player record, the level, the far blocks' segments, the frame buffer, the graphics library's data). UW2Decomp's `src/replay/REPLAY.C` is replay.c with these in it.

- `fuzz_targets.py` and `fuzzhost-uw2.c`: tools/fuzzasm.py's 35 UW2 targets (IMATH, INSTANCE, SPHERE, GRENTRY, CLIP, EXPAND) and fuzzhost.c's UW2 side (the far data, seg021's data and the code block as regions; cSinCos, cFstSinCos, cSqRt, cAtan2 and seg004_uncmp as call kinds).

- `asm2c_spec.py`: tools/asm2c.py's spec: the 26 modules UW2Decomp translates (14 of seg004, 11 of seg003, IMATH), the code segments, the hand-written ranges, the C names the overrides use. The overrides themselves, C for single instructions of UW2's, are UW2Decomp's tools/asm2c.py's (`[asm2c] overrides`).
- `asmgame.h`: UW2's side of runtime/port/x86/asmrt.h (the code block of seg003 and seg004, seg003's own dispatcher for its hand-written span writers, the trace variable). The renderer's divide fault handlers, `asm_divfault`, are UW2Decomp's src/port/x86/divfault.c.

- `compat-uw2.h`, `plat-uw2.h`, `portgame.h`, `nulls-uw2.c`: UW2's lines for runtime/port/compat.h (the game's main is uw2_main) and plat.h (the messages' prefix, the default title), its portgame.h for runtime/port/port.h (uw2port, DGROUP at paragraph 65E9h with `_ctype` at DS:1BF6, seg021's exit chain, the far blocks), and what DOS reads through UW2's null pointers (the overlay stub's tail at DS:0, the vectors DOSBox sets up, int0_trap at int 0).

- `ailgame.h`: UW2's for runtime/port/sound/ail.c: compat.h, then UW2's sound.h, the game's own declarations of the AIL API, and `AIL_FM_EXT`, `uw2_tvfx`: the FM drivers' time-variant effects (Origin's ALE.INC, translated from DM03.ADV), which UW2Decomp defines in src/port/sound/tvfx.c and which plug into runtime/port/sound/yamaha.c through yamaha.h's `struct AilFmExt`. `[sound] drivers` in exhume.toml names UW2's driver file for each kind, for tools/ailcheck.py; `[sound] extensions` names tvfx.c.

`../prove-port.sh` proves the tools and the runtime on a snapshot of UW2Decomp, writing nothing into the checkout (`PATCH=FILE` applies a change for UW2Decomp to every snapshot first, to prove it before it is committed there):

- `build`: Exhume's gate passes; Exhume's portbuild.py links a `uw2port` byte-identical to the one UW2Decomp's own portbuild.py links in the same tree (all 173 objects equal; 175 with the UW2Decomp patch that moves tvfx.c and divfault.c into files of their own); Exhume's replay DOS build is the EXE the committed goldens were made with (the same SHA-256).
- `verify`: Exhume's `replay.py verify all` finds all eight sessions identical to UW2Decomp's committed goldens, at all 550 checkpoints, saved games included. With `--dos`, `replay.py golden all --check` replays each session twice in DOSBox-X and finds both runs identical to the golden.
- `runtime`: with portable-uw2.h and runtime/include/portable.h as `src/include/portable.h`, rpgame.h in `src/include`, and runtime/replay/replay.c as `src/replay/REPLAY.C`, the gate passes (so no DOS byte changed), and the port verifies all eight sessions; with `--dos` the replay DOS build made from Exhume's replay.c reproduces every golden in DOSBox-X, each session twice.
- `fuzz`: Exhume's fuzzasm.py with these targets runs 5,560 cases of the 35 routines with no difference, the same report as UW2Decomp's fuzzasm.py but for the timings; a target changed to compare registers the C is known not to set (`expand.pal_63` with every register) fails in every case, so the comparison is live.
- `asm2c`: Exhume's asm2c.py --check finds UW2Decomp's translations up to date; with the 27 generated files deleted from a snapshot, it writes all 27 again byte-identical to UW2Decomp's committed ones; and with runtime/port/x86/asmrt.h and asmrt.c and asmgame.h in place of UW2Decomp's asmrt (UW2Decomp's divfault.c kept), the port builds, verifies all eight sessions and fuzzes clean.
- `toolkit`: Exhume's portcheck.py, portstubs.py --check, widths.py --diff, intaudit.py and layoutcheck.py give the same output as UW2Decomp's own tools in the same tree (layoutcheck's DOS and host probe outputs too: 46 records, 38 identical, every file record identical); and with Exhume's whole portability layer installed in place of UW2Decomp's (portable.h, REPLAY.C, compat.h, the stand-in headers, port.h, plat.h, files.c, png.c, the SDL3 backend, parmap.c, frame.c, vga.c, records.c, crash.c, borland.c, the stubs' body and asmrt, with the bindings above), the gate passes, the port builds and verifies all eight sessions, the fuzzing finds no difference, the stubs are current and portcheck reports 0 errors.
- `sound`: Exhume's ailcheck.py on UW2Decomp's port finds every register write and MIDI byte identical to the real drivers' (DM03.ADV: 13,608 writes over 195 calls in `sound`, 14,041 over 270 in `soundfm`; DM05.ADV: 25,726 bytes over 280 calls in `soundmt`); and with runtime/port/sound and sys/pit.c in place as well (UW2Decomp's tvfx.c plugged into yamaha.c's hook) (the config's third-party macros renamed to the runtime's), the gate passes, every session verifies, ailcheck gives the same three results, the fuzzing is clean, and the WAV file of everything the cards play in the whole `sound` and `soundfm` sessions is byte-identical to the one UW2Decomp's own port renders.
- `ci`: tools/citemplates.py with examples/uw2/ci.toml writes UW2Decomp's four workflows and two actions byte-identical to its committed `.github` (at the CI commit `6252fdf` and at today's HEAD), and actionlint finds nothing in them or in the defaults' instantiation; tools/ci-assets.sh, given UW2's paths, prints and writes what UW2Decomp's own does on a dummy bundle encrypted with a throwaway age key.
