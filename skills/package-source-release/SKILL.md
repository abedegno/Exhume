# Package a source release

Publish a reviewed source boundary with reproducible dependency declarations. An exact private build does not establish a reproducible or redistributable public tree.

1. Freeze the recovery commit and inventory **all tracked files**, including gitlinks and hidden/session directories. Classify reusable tools, project source, historical evidence, compiler knowledge, optional separately licensed tools and restricted inputs. Record path/rule/counts; do not embed source bodies or personal absolute paths in the audit.
2. Read actual component/file headers, original notices, submodule licenses and provenance. Preserve GPL notices, Build and Open Watcom terms and all other applicable notices separately. A blanket repository license cannot relicense them. Distinguish primary license terms and original release grants from cautious recovery-authored checkpoint statements; a prior “not authorized” research note is not itself a vendor license restriction. Record contradictory evidence as unresolved instead of inventing a prohibition. Public availability alone is insufficient.
3. Build a curated tree using an explicit allowlist and reject executables, objects, compiler/SDK libraries, media, game assets, tool homes, caches, logs with personal paths and source-bearing private evidence. Inspect both filenames and file signatures. Keep restricted vendor-derived source **and associated derived sources/metadata** outside public Git history.
4. Generate a relative-path SHA-256 manifest for the reviewed public source and a separate exact manifest of locally required restricted source. Supply a local importer that rejects missing, altered, unexpected, escaping or symlinked inputs, verifies the entire input set before copying, and checks staged bytes against frozen pre-copy hashes. An importer grants no distribution rights and must not silently accept licenses or execute vendor installers.
5. Pin submodule commits, tool-source archives, compiler/assembler versions, options, ABI, headers, selected stock members/libraries, native FILE order, banks and vendor prefix. State which dependencies the user supplies and which nodes earn recovered-source credit. Optional GNU/binutils/objconv patches remain in their separately licensed pipeline; link the audited external implementation rather than copying GPL tool source into MIT core.
6. From the **curated checkout**, import only the declared local overlay and install declared dependencies, then compile every owned node in a fresh child. Do not validate by linking private recovery objects or merely hashing its old executable. Freeze RAW outputs before parse/copy/publication. Run required rejection cases under normal Python and `python3 -O` when changing validators. An independent observer checks full extent, SHA-256 and unmasked equality, separate from the producer. Record the curated commit/source snapshot, dependency manifest, command, source-node count and result.
7. Review the final staged/tracked tree for publication boundaries and portable links. Public CI may validate manifests/rights boundaries without claiming to build unavailable private dependencies. Complete the package and evidence within standing authorization; request publication approval only if the user has not authorized that external step.

The report states C versus assembly emitters and C reading aids, unidentified preserved DATA and its zero historical-source credit, supplied vendor/runtime components, remaining limits and the exact proof level. Retain earlier failures as history without presenting them as the current result. See [the Duke case study](../../docs/case-study-duke3d.md) for a fresh curated-tree proof and local-overlay boundary.
